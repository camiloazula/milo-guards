# milo-guards 0.2.1

A patch release with security fixes. What a guard answers changes, and what a
caller compiles against does not. Every detail is in
[the changelog](../../CHANGELOG.md#021-2026-11-28); this page is what a
caller needs to know to upgrade.

## Upgrade

- No change to a `"0.2"` requirement or to your Rust: run `cargo update -p
  milo-guards` (or a caller's own crate name, if it depends on a single guard)
  and rebuild. The crates still declare Rust 1.90, and `just semver` finds no
  change to any crate's public API.
- Some answers are more serious than 0.2.0's: the shell guard reads more of
  what a command line does. A line that was `safe` may now be `delete`,
  `read_secret`, `overwrite`, `unknown` or `unreadable`. No line that was
  risky in 0.2.0 is safe, and none loses a finding. Of the 2,934 everyday
  commands the guards are measured on, 2,908 are still `safe` (a false-alarm
  share of 0.9 %: 0.3 % in a POSIX shell, none in PowerShell, 4.6 % in cmd),
  and none of their answers moved.

## Security fixes

- The shell guard reads a brace list or a sequence among a program's
  arguments as the words the shell makes of it, as bash, zsh and ksh do before
  the program runs, so what a program is handed is judged for every shell,
  interpreter, launcher and wrapper. The line as written is judged too, since
  dash and ash spell nothing out, and the answer is every finding of either. A
  list the guard cannot spell out, or a program that changes how the shell
  reads the rest of the line, is `unknown`.
- A word the shell's grammar cuts in two, where a quote is followed by an
  escaped blank, a backslash or a comment, is no longer read as one: the line
  is `unknown`. A backslash followed by a carriage return and a line feed is
  `unreadable`, as a control character.
- A line of many long lists, of many arguments to a program that compares them
  all (`rsync`), or of many commands that run inline code, is read in time
  that grows with its length, as the other lines are.

The advisories are linked from this release's page on GitHub.

## Deliberate limits

- A line the guard does not read as the shell does is `unknown`, not `safe`:
  the more cautious answer, which makes a few lines with an escaped blank after
  a quote, or a `\` at the end of a word, false alarms. The share of everyday
  commands it touches is none.
- The code reader still reads at most 3 KiB of code, as in 0.2.0; a later
  release raises it.

## New

Nothing. This release changes what the guards answer, not what they offer.

## Not in this release

Ruby, Perl, PHP and Lua given inline are still `unknown`
([#305](https://github.com/camiloazula/milo-guards/issues/305)).
