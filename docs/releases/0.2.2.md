# milo-guards 0.2.2

A patch release with security fixes. What a guard answers changes, and what a
caller compiles against does not. Every detail is in
[the changelog](../../CHANGELOG.md#022-2026-11-28); this page is what a
caller needs to know to upgrade.

## Upgrade

- No change to a `"0.2"` requirement or to your Rust: run `cargo update -p
  milo-guards` (or a caller's own crate name, if it depends on a single guard)
  and rebuild. The crates still declare Rust 1.90, and `just semver` finds no
  change to any crate's public API.
- Some answers are more serious than 0.2.1's: the shell guard reads more of
  what a command line does. A line that was `safe` may now be `delete`,
  `read_secret`, `send_secret`, `overwrite`, `unknown` or `unreadable`, and a
  line a shell is handed with a letter it has no table for is `unknown` where
  it was judged as the command it names. A few lines 0.2.1 judged risky are
  now `safe`, because fish's, csh's and tcsh's options are read as those shells
  read them, and a word that is no script or command to them is not judged as one.
  Of the 2,934 everyday commands the guards are measured on, 2,908 are
  still `safe` (a false-alarm share of 0.9 %: 0.3 % in a POSIX shell, none in
  PowerShell, 4.6 % in cmd), and none of their answers moved.

## Security fixes

- The shell guard reads the value an option takes wherever the option stands:
  attached to a short option, after `=`, or taken by the last flag of a
  cluster, so the file a program reads or sends, and where a download lands,
  are judged as the program takes them. A copy from another machine is judged
  by every place on this machine it may land.
- A word the shell does not expand to the home directory because of how it is
  quoted is judged as the home directory and as a name in the working
  directory.
- On Windows, the switches and drive paths that Git Bash and MSYS2 hand on to
  a Windows program are read as the program gets them, and an administrative
  share of this machine is placed on its disk by every spelling of the
  loopback address.
- A cmd line is split at the operators after a quote that a caret or a line
  break escaped, and a redirect after the value of a `set` is judged.
- "Runs a script outside the workspace" is said of a script a shell or an
  interpreter runs from a file, and of a program a shell's command string
  starts by a path, never of a command string or the line's input, which their
  own rules judge. Each shell is read with the letters and options it has
  (also under the other names it is known by), fish with every command it is
  given, and csh and tcsh with theirs; a letter or option a shell's table
  does not have, or that two shells of one name read differently, is
  `unknown`.
- What a line does past a NUL is read, besides the line being `unreadable`.
- `split` and `csplit`, and the command `split` runs on each piece, are read:
  the file they cut, the pieces they write, and what they run.
- The commands wget runs from its options, and the files curl and wget read
  their options and variables from, are read.
- The name an `export` or a `declare` is given is read as the shell reads it,
  so the variables the commands after it read are found however the name is
  written.

The advisories are linked from this release's page on GitHub.

## Deliberate limits

- A line the guard does not read as the shell does is `unknown`, not `safe`:
  the more cautious answer. The share of everyday commands it touches is
  none.
- The code reader still reads at most 3 KiB of code, as in 0.2.0; a later
  release raises it.

## New

Nothing. This release changes what the guards answer, not what they offer.

## Not in this release

Ruby, Perl, PHP and Lua given inline are still `unknown`
([#305](https://github.com/camiloazula/milo-guards/issues/305)).
