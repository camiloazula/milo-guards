# milo-guards 0.3.0

A minor release: Ruby is read. What a caller compiles against grows, and the
guards judge more of what an agent runs. Every detail is in
[the changelog](../../CHANGELOG.md#030-2026-11-28); this page is what a
caller needs to know to upgrade.

## Upgrade

- Move your requirement from `"0.2"` to `"0.3"`. The crates still declare
  Rust 1.90.
- `milo_guards_code::Language` has a new variant, `Ruby`, and the enum is
  exhaustive: a caller that matches on it without a wildcard arm must add an
  arm for `Ruby`, and the build fails until it does. A caller that matches
  with a wildcard arm builds as it did, and takes the variant as the arm for
  any other language; a caller that passes a `Language` to the code reader,
  the shell guard or the script guard needs nothing else. This is the one
  change to the crates' public API that breaks a build (`just semver` reports
  it as a variant added to an exhaustive enum), and so the minor bump.
- The code reader has a new function, `milo_guards_code::refusal`, which
  says in words why it does not parse code, as the script guard now gives it
  for `unreadable`. A caller that does not call it changes nothing.
- A new dependency, tree-sitter-ruby 0.23, is built from C beside the other
  grammars, behind the `ruby` feature of the code reader, the shell guard
  and the script guard, which is on by default. A caller that wants no Ruby
  turns it off (`default-features = false`) as it does the other features:
  `Language::Ruby` is still there, and Ruby is `unknown` to the shell guard
  and `unreadable` to the script guard, as it was in 0.2.2.
- Some answers are more serious than 0.2.2's. A line that runs Ruby, one of
  the tools around it (`ruby`, `irb`, `rake`, `rails`, `bundle`, `gem` and the
  version managers) or a variable they read is judged by what it does, so a
  line that was `safe` may now be `unknown` or a finding of its own; and
  inline Python and JavaScript in a loop, a function or a trap is read whole
  only when the line sets no variable anywhere, as what follows it may change
  what it runs. A variable exported under a quoted or escaped name with an
  append, and one csh, tcsh or fish exports, is read as `export` reads it, so
  a line that was `safe` may be a finding of its own. Of the 2,934 everyday
  commands the guards are measured on, 2,908 are still `safe` (a false-alarm
  share of 0.9 %: 0.3 % in a POSIX shell, none in PowerShell, 4.6 % in cmd),
  and none of their answers moved.

## Security fixes

- Ruby given to `ruby`, `jruby`, `truffleruby` or `irb`, inline or on their
  input, is read for what it deletes, writes, reads, moves and runs, and is
  `unknown` when the guard cannot read it whole. Before, all of it was
  `unknown` and none of it was read.
- What Ruby loads that the line does not show is judged by where it is: the
  libraries and load paths of its options, the variables it reads for them
  and for the folders it works in, the settings of bundler and RubyGems, a
  Rails template, and a project a runner sets up from a file or a folder
  outside the workspace. A line that sets more of them than the guard places
  one by one is `unknown`.
- The runners and tools of Ruby (`bundle exec`, the version managers, `gem
  exec`, `rake`, `rails`) judge what they run, and what they run in a folder
  other than the workspace's is `unknown`.
- Ruby the grammar reads otherwise than Ruby does, or past what the grammar's
  scanner keeps, is not read: `unknown` to the shell guard and `unreadable`
  to the script guard, with its reason. Ruby is held to what Python and
  JavaScript are held to: code of at most 3 KiB, one budget of work for every
  reading, and no code read through a syntax error.
- The shell guard reads a name an `export`, a `declare` or the like is given
  with an append (`+=`) as the variable before the `+` whatever its quoting
  or escaping, so the rules that read a variable (a program's options, its
  proxy, its pager, the command it runs to reach a remote, the options of
  node, python and zip, the file a shell runs first) find it. An append to a
  variable that holds one path, to a value the line did not set, is only
  known when it runs.
- The variables csh, tcsh and fish export in the commands those shells are
  given (`setenv`, and fish's `set`, with or without `--export`) are read as
  the variables `export` sets, for the programs the line starts after them;
  a fish `set` that erases, queries, names or shows a variable, or has `-u`,
  sets none.

The advisories are linked from this release's page on GitHub.

## Deliberate limits

- The code reader still reads at most 3 KiB of code, as in 0.2.0, Ruby
  included; a later release raises it.
- Ruby the guard does not read whole is `unknown`, not `safe`: the REPLs and
  embedded Rubies it cannot place (`mruby`, `pry`, `rails runner`), the
  options it cannot place (`-S` with others that load or move code, the
  encoding options), and Ruby's own `require` and `load`. The share of
  everyday commands it touches is none.

## New

- **Ruby**: `Language::Ruby`, read by the code reader, the shell guard (`ruby
  -e` and Ruby on the input of `ruby` and `irb`, with where each piece of
  code is, for `locate`) and the script guard.
- **`milo_guards_code::refusal`**: why the reader refuses code before it
  parses it.
- The `ruby` features of the code reader, the shell guard and the script
  guard, on by default.

## Not in this release

Perl, PHP and Lua given inline are still `unknown`
([#305](https://github.com/camiloazula/milo-guards/issues/305)).
